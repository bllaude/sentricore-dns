Documentation

Everything you can configure, in one page. The authoritative source lives in the repo's README; this mirrors it for reading comfort.

Requirements

  • Python 3.11+
  • Dependencies: dnslib, Flask, gunicorn (see requirements.txt)
  • A free UDP port for the proxy (default 5300) and a TCP port for the dashboard (default 5000)

Configuration reference (config.json)

KeyDescription
upstream_dnsUpstream DNS server [IP, port] (default 1.1.1.1:53).
listen_addressProxy listen address [IP, port] (default 0.0.0.0:5300).
blocklist_pathPrimary blocklist file path.
blocklist_sourcesArray of blocklist paths or URLs, merged on load/reload.
blocklist_update_intervalSeconds between automatic blocklist reloads.
cache_ttlDNS response cache TTL in seconds.
cache_max_sizeMaximum number of cached responses (LRU eviction).
database_pathPath to the SQLite database.
log_file / log_levelProxy log file location and level.
rate_limit_per_client_qpsSustained queries-per-second allowed per client IP.
rate_limit_burstToken-bucket burst allowance per client IP.
db_flush_intervalSeconds between batched writes of query logs/metrics to SQLite.

Environment variables (web app)

VariableDescription
SENTRICORE_CONFIGAlternate path to config.json.
SENTRICORE_DBOverride database path.
SENTRICORE_API_KEY / DASHBOARD_API_KEYShared secret required for write API endpoints.
SENTRICORE_DENY_WRITES_WITHOUT_KEYSet to 0 to allow writes when no API key is configured (default: deny).
SENTRICORE_WEB_HOST / SENTRICORE_WEB_PORTDashboard bind host/port (default 127.0.0.1:5000).
FLASK_DEBUGSet to 1 to enable Flask debug mode.

Useful expressions once scraping:

rate(sentricore_total_queries[5m])
rate(sentricore_blocked_queries[5m])
sentricore_cache_hits / (sentricore_cache_hits + sentricore_cache_misses)

Working with blocklists

Static lists: drop files under blocklists/ (one domain per line; ad-block style hosts entries like 0.0.0.0 domain are normalized automatically). All blocklist_sources — files or URLs — are merged and reloaded every blocklist_update_interval seconds with no restart needed.

Dynamic entries: manage domains at runtime through the REST API; changes persist to the database. Full details in the API reference.
